SDLC skill → GitHub Copilot: what actually differs

Every claim below was checked against current VS Code / GitHub docs; each carries its proof link.
Headline: There are no missing concepts. Copilot supports skills, instructions, prompt files, subagents, hooks, and MCP — the same building blocks your sdlc skill governs, on the same open Agent Skills standard. So porting is path & format remapping, not "rewrite because feature X is absent." The review philosophy and the guideline-rule checklist port unchanged.
Correction log (my earlier mistakes, now fixed): I wrongly claimed at various points that Copilot has "no skill concept," "no true subagents," "no hooks," and doesn't read CLAUDE.md. All four were wrong — corrected and sourced below. Treat every item here as verified, not remembered.
Differences to remap (each verified)
  • Skill location path Your skill sits at .cursor/skills/sdlc, which is not one of Copilot's load paths. Copilot reads project skills from .github/skills, .claude/skills, or .agents/skills (personal: ~/.copilot/skills, ~/.agents/skills). To share across both tools, host under .claude/skills or .agents/skills — but confirm Cursor's own supported locations, which I have not verified here. GitHub Docs — About agent skills
  • Rules → instructions files format Cursor rules are .cursor/rules/*.mdc with globs/alwaysApply. Copilot's equivalent is .github/instructions/*.instructions.md using an applyTo glob in YAML frontmatter, plus the always-on .github/copilot-instructions.md. Same idea, different filename, extension, and frontmatter field — the routing row and rule-checklist must point here. VS Code Docs — Custom instructions
  • Commands → prompt files path Cursor .cursor/commands/*.md maps to Copilot prompt files at .github/prompts/*.prompt.md, invoked with /name in chat (or via "Chat: Run Prompt"). Concept matches; re-point the path and frontmatter. VS Code Docs — Prompt files
  • Subagents path Copilot has genuine subagents (formerly "custom chat modes") with context isolation, parallelism, and roles. Cursor .cursor/agents/*.md → Copilot .github/agents/*.agent.md, with frontmatter like user-invocable and disable-model-invocation plus its own model/tools. Clean path + frontmatter remap. VS Code Docs — Subagents
  • Hooks format Copilot does have hooks (Preview). Cursor's .cursor/hooks.json maps to Copilot hook JSON in .github/hooks/, mapping lifecycle events (SessionStart, PreToolUse, PostToolUse, SubagentStart/Stop, PreCompact, Stop) to shell commands via stdin/stdout JSON. Keep the hook checklist; retarget path and align event names. VS Code Docs — Agent hooks · GitHub Docs — Hooks reference
  • MCP / harness config path Cursor's mcp.json/settings.json map to Copilot's .vscode/mcp.json (workspace, source-controllable) and a user-profile mcp.json (via "MCP: Open User Configuration"). Other harness settings live in VS Code settings. Different files; the "other" checklist retargets here. VS Code Docs — MCP servers
  • Context files path Copilot's always-on context file is .github/copilot-instructions.md, and it also reads both AGENTS.md and CLAUDE.md (workspace root, .claude folder, or home). So the context-file checklist keeps CLAUDE.md/AGENTS.md and adds copilot-instructions.md. (Nested AGENTS.md needs chat.useNestedAgentsMdFiles.) VS Code Docs — Custom instructions
  • Dedup search globs path The guideline checklist's "not duplicated" check greps .cursor/skills/**, .cursor/rules/*.mdc, .cursor/commands/*.md. Repoint to the Copilot paths above (.github/skills, .github/instructions, .github/prompts, .claude/skills) so dedup covers the real files. Derived from the location facts in the linked skill/instructions docs. GitHub Docs — About agent skills
  • Skill frontmatter fields confirm Your SKILL.md declares allowed-tools (Read, Grep, Shell, StrReplace…) — Cursor's tool identifiers. Because Copilot follows the open Agent Skills spec, name/description carry over, but the exact tool-permission field name and accepted tool IDs should be confirmed against the spec before relying on them. This is the one item I could not fully pin down in the docs. GitHub Docs — About agent skills (defers exact schema to the open spec)
